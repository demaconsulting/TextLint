# Tool names: a hand-curated, living list of developer tools, and the frameworks, languages, and file formats that
# come with them.
# This file is owned by the project and is NEVER overwritten by dictionaries/refresh.py. It is not generated and not
# pinned to any upstream list; the owner extends it on request, and each entry is written for this project from its
# own review. Lines that start with a hash are comments; blank lines are ignored. Sections are for the reader only.
#
# To add a tool, all of these must hold:
#   - The entry is the real, public name of a tool or product (not a fragment of a name, not an abbreviation of
#     one project, not a person, not an internal identifier), and its documentation is public.
#   - The entry is not a misspelling of an ordinary word (every entry was checked against the crate-ci/typos
#     list of known typos), and no entry may be added to make a spelling error go away.
#   - The entry is not already known: not in another list of dictionaries/, so that it has one home only.
#   - It is one lowercase word of letters (and inner straight apostrophes): no digits, hyphens, spaces, or dots.
#     A name with a digit or hyphen (flake8, pre-commit) is split by the tokenizer into parts that are checked alone.
#   - It is at least as long as the default minimum word length (4 letters); a shorter name is never checked.
#   - It is not a US-only or GB-only spelling variant: the dictionary builder removes those from this folder.
# Keep each section sorted. The library tests look up every entry in every language selection.
#
# Homebrew 365-day install analytics (formulae and casks) guided the choice of the common developer tools; no list
# was copied from it.
